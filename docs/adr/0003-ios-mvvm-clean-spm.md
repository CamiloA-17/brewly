# ADR 0003: iOS with MVVM + Clean Architecture in SPM modules

- Status: accepted
- Date: 2026-09-25

## Context

The app will grow into several features (recipes, beans, feed, profiles…) and needs to stay
testable without heavy third-party architecture frameworks. The alternatives were The Composable
Architecture and a lighter "MV" approach.

## Decision

- **MVVM + Clean Architecture:** SwiftUI views, `@MainActor @Observable` view models, a domain
  layer with entities, repository protocols and use cases, and a data layer that implements the
  repositories over the API.
- All code lives in the local package **BrewlyKit**, one module per layer and per feature.
  Features depend only on `BrewlyDomain` and `BrewlyDesignSystem`; `AppFeature` is the
  composition root.
- The Xcode project is generated by **XcodeGen** from `ios/project.yml` and not committed.
- iOS 17 is the minimum version (Observation framework); Swift 6 language mode.

## Consequences

- Module boundaries enforce the dependency rule at compile time, and view models are tested with
  fake repositories.
- Some mapping code between DTOs and domain entities.
- Contributors need XcodeGen (`brew install xcodegen`) to open the project.
